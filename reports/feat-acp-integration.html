Request changes

The basic Zed flow works. initialize, session/new, model selection, streamed text, tool calls and session/load replay all ran against a real OpenRouter model over stdio. Four problems block merging:

  • F1 Cancelling a turn answers end_turn instead of cancelled, and shows the user a fake error message.
  • F2 Failed turns are reported as successful end_turn, often with no error text at all.
  • F3 src/acp/handlers.ts imports harness internals by relative path (../../../harness/src/…), which breaks the package boundary.
  • F4 session/new never sets the session's host directory, so project settings and project plugins are ignored for every ACP session.

All four can be fixed in packages/codework without changing the core.

Step 4

Findings in the ACP layer

Each of these can be fixed inside packages/codework/src/acp with the harness APIs that exist today. File references are to the merged tree.

F1highCancellation answers end_turn and shows a fake error
Where
src/acp/handlers.ts (prompt, cancel) · src/acp/feed.ts (session.llm.failed)
Cause
cancel calls control.interrupt, which stops the execution fiber, not the control.run call that session/prompt is waiting on. run returns normally once the session is idle, so Effect.catchCauseIf(Cause.hasInterrupts, …) never fires. The aborted LLM request then publishes LLMFailed with reason: "aborted", which the feed renders as "❌ Error: LLM request failed".
Spec
On session/cancel, the agent must answer the original session/prompt with StopReason::Cancelled.
Fix
Record the cancellation per session in cancel, or watch for EventList.ExecutionInterrupted while the prompt runs, and return cancelled when it is seen. Drop LLMFailed events whose reason is "aborted". Add a test that cancels a slow fake LLM.
F2highFailed turns are reported as successful
Where
src/acp/handlers.ts prompt · src/acp/feed.ts toSessionUpdate
Cause
control.run resolves with Admitted whether the turn succeeded or not, and the handler always maps that to end_turn. When the run fails before the LLM starts (unknown model, missing catalog, missing credentials), nothing is streamed: ExecutionFailed is not mapped. When the LLM does fail, the feed looks for data.errorMessage or data.failure.message. Neither exists on LLMFailed, which carries the text in data.message.errorMessage, so the user always sees "LLM request failed". Also, LLMEnded.reason === "length" is never mapped to max_tokens.
Evidence
Live: after an invalid model, end_turn in 17 ms with 0 updates. After a restart, a generic error and end_turn. In tests: without models.gen.json, the streaming test gets 0 updates but still sees end_turn.
Fix
While the prompt runs, collect the terminal execution event for the session. For ExecutionFailed, fail the request with a JSON-RPC error that carries SessionFailure's message. For a last LLMEnded with reason length, return max_tokens. Use Schema.is(EventList.X) guards, as cli/cmd/handlers/run.ts does. Core suggestion S3 would make this simpler.
F3highRelative imports into the harness source tree
Where
src/acp/handlers.ts: import * as SandboxController from "../../../harness/src/sandbox/control.ts" and import * as SessionRuntime from "../../../harness/src/session/runtime.ts"
Why it matters
The CLI's vp pack keeps @codeworksh/harness external, but it bundles relative files. The published CLI would therefore ship a second, private copy of harness modules next to the real dependency. It also couples the CLI to harness file layout and undoes the rule that packages/codework consumes the harness only through its public exports. server/handlers.ts manages the same operations without any of this.
Fix
Use Session.attach({ sessionId, model: { provider, id }, thinkingLevel }) from @codeworksh/harness/effect to change config. It merges into the runtime bindings, exactly what runtime.update does now. To capture requirements, don't name internal services. Type the captured context from the public function, e.g. Effect.Services<ReturnType<typeof Session.create>>, or provide the harness layer per call. With both changes, the SqlClient and SandboxController yields in Handlers.layer can go. Reading the current binding back (runtime.get) has no public API; see S1. Until S1 lands, the ACP layer can keep its own record of the values it set.
F4highsession/new doesn't link the session to its project
Where
src/acp/handlers.ts newSession: Session.create(cwd === undefined ? {} : { directory: cwd })
Cause
In the harness, directory is where the work runs inside the session's space. hostDir is the host project whose settings and plugins apply. Both run and server/handlers.ts pass hostDir. ACP passes only directory, so project settings.jsonc, project plugins and project model defaults never apply. loadSession then reads hostDir as undefined, and the config options it computes come from user settings only. The handler also calls settings.load(cwd) for display, so the dropdown can show a model the session won't actually use.
Spec
The cwd must be used for the session regardless of where the agent subprocess was spawned.
Fix
Session.create({ directory: cwd, hostDir: cwd, title: … }). ACP guarantees cwd is absolute, which is what declaredHostDir requires.
F5mediumModel ids containing “/” are mangled for display
Where
src/acp/config.ts resolveConfigOptions, lines 40–46
Cause
When model contains a slash, the code cuts everything before it even though provider was already given. OpenRouter ids such as meta/muse-spark-1.3-contributor become muse-spark-1.3-contributor. The aikit lookup for that id then fails, the current value matches no option (so a synthetic entry is added), and thinking levels fall back to a hard-coded list.
Fix
Split on the first slash only when no provider is given. Better: keep a single parse function for the provider/model value and use it in both setConfigOption and resolveConfigOptions, since the two currently parse it separately.
F6mediumset_config_option accepts any value
Where
src/acp/handlers.ts setConfigOption
Cause
value as Model.ThinkingLevel stores any string. An unknown model id is stored as-is. An unknown configId is ignored without complaint. The client is never told, and the next prompt fails silently (F2).
Fix
Validate against the options just offered: decode the thinking level with a Schema literal and require the model to be in the catalog. Answer invalid input with RequestError.invalidParams.
F7mediumTyped errors become empty internal errors
Where
src/acp/server.ts makeApp: Effect.runPromise(handler)
Cause
A failed Effect rejects with a FiberFailure, and the SDK turns that into -32603 with data: {}. SessionNotFoundError, PromptConflictError, location and sandbox errors all lose their meaning.
Fix
Wrap each handler once: map SessionNotFoundError to RequestError.resourceNotFound, validation errors to invalidParams, and everything else to internalError with the error's message. Keep this in server.ts so the handlers stay unchanged.
F8mediumHard-coded defaults and model lists that duplicate core settings
Where
src/acp/config.ts
Cause
The default openai/gpt-5.6-luna/high copies defaults in packages/plugin/src/settings.ts. Settings.load always returns a merged model, so this fallback can never be reached correctly. The fallback option list names models that may not exist (anthropic/claude-3-7-sonnet, google/gemini-3.8-flash). The code always adds google, openai and anthropic whether or not they have credentials, detects keys through a globalThis.process cast, and ignores OAuth logins (codework auth). The result: 395 options in the live test.
Fix
Take defaults from Settings.load only. Build the list from providers that actually have credentials, including OAuth; see S10. Delete the static fallback list.
F9mediumsession/list: prefix match, wrong field, no paging
Where
src/acp/handlers.ts listSessions
Cause
The filter row.directory.startsWith(cwd) matches /a/b2 for /a/b, and it matches every child directory. It also filters the in-space directory rather than the host project. cursor and nextCursor aren't supported, so every session in the database is returned.
Fix
Compare hostDir exactly, or at most use a cwd + "/" prefix. Page with an opaque cursor over the rows list() already returns, newest first.
F10mediumThe event feed and history replay are untyped
Where
src/acp/feed.ts
Cause
toSessionUpdate matches events with event.type.startsWith(…) and as Record<string, unknown> casts, while EventList already exports a schema for each event. This is how F2's wrong field went unnoticed. entryToSessionUpdates hand-parses stored part JSON, guesses between shapes (callID/callId, text/thinking), and ignores parse errors with empty catch {}. It is about 170 lines for what is a decode of stored aikit parts.
Fix
Use Schema.is(EventList.LLMTextDelta) and the other guards, as run.ts does. For replay, decode each part with aikit's part types (one switch on part.type), or use a public transcript decoder (S8).
F11lowConcurrent prompts duplicate updates
Where
src/acp/handlers.ts prompt
Cause
Each session/prompt registers its own events.listen for the session. A second prompt while one is running uses delivery: "steer", joins the running turn, and forwards every update a second time. Found by reading the code; I didn't reproduce it.
Fix
Keep one forwarder per session and connection, or reject a second prompt while one is in flight.
F12lowResource links lose their URI
Where
src/acp/handlers.ts extractPromptText
Cause
ACP requires every agent to support resource_link. The handler turns a link into [Resource: name], which drops the URI the model needs to open the file. Image and audio blocks are dropped without any signal. This is correct only because promptCapabilities isn't advertised, and the live test showed a client may send them anyway.
Fix
Include the URI (and mimeType when present). Log or reject unsupported block types.
F13lowTool kind guessed from substrings
Where
src/acp/feed.ts toolKind, toolTitle
Cause
Substring checks misfire: rm matches "format", cat matches "locate", run matches "prune". toolTitle also checks argument names (CommandLine, AbsolutePath, TargetFile) that no tool in this repo has. The only built-in tool is bash.
Fix
Map known tool names exactly and let plugin tools declare their own kind (S7). Default to other.
F14lowUnused barrels and dead code
Where
src/acp/contract.ts, src/acp/index.ts, feed.ts streamUpdates
Cause
contract.ts re-exports the whole SDK twice (export * and export type *), and nothing imports it. index.ts is also unused, and so is streamUpdates.
Fix
Delete them.
F15lowTest gaps
Where
test/acp.test.ts
Cause
The cancel test only checks an idle session. Nothing covers a failed turn, invalid config values, hostDir, the list filter, or ids containing a slash, so F1, F2, F4, F5 and F6 all pass the suite. The gpt-4o assertion depends on the downloaded catalog. That matches the other suites, but it deserves a comment.
Fix
Add one test per high and medium finding above, using the existing fake LLM fixtures (immediateOpen, toolTurn) and a slow fake stream for cancel.

Step 6

What the core can’t support, and what would help

Per the brief, packages/harness wasn't modified. The gaps below block ACP features outright. Each has a suggested core change; where a change would belong to the plugin contract instead, that's noted.

GapACP impactSuggested core change
G1 No tool approval stepNo session/request_permission. In the live test the model read files outside the project without being asked.S5 Add an approval hook to the runner before a tool runs, e.g. an approve(call) → allow | deny | allowAlways service with a default of allow. ACP would implement it with request_permission, and a TUI could reuse it.
G2 Tools only use the harness sandboxCan't use the client's fs or terminal, so the editor's unsaved buffers and terminal view aren't used.S12 A sandbox driver backed by the ACP client's fs and terminal. The driver contract lives in packages/plugin, so this may need no harness change, but a driver would need access to the per-session connection. Worth a design note first.
G3 Prompts are text onlyNo image, audio or embedded-resource prompts.S6 Grow PromptSchema.Prompt into content parts that aikit already supports; this is the existing TODO in session/prompt/schema.ts.
G4 No MCP clientFails a spec MUST (stdio MCP servers from session/new).S7 An MCP tool source, ideally a plugin whose tools are registered per session from mcpServers. Let tools declare an ACP-style kind at the same time (helps F13).
G5 No agent modesNo set_mode or mode updates.Defer until there is a real second mode (ask vs. code, for example). Per the project guidelines, don't design for it early.
G6 Session config lives only in memoryAfter a restart, a loaded session loses its model and thinking level. Confirmed live.S2 Persist runtime bindings, e.g. revive the commented-out session.config.changed durable event in event/list.ts and project it back on load.
G7 No plan or structured edit eventsNo plan, diff content or locations.Comes with future file-edit and todo tools. Nothing to do now.
G8 No session title APIEvery session is titled "Session" in session/list, with no session_info_update.S9 Session.rename, with an optional title from the first prompt.
G9 ToolStarted has no argumentsThe first tool_call shows only "bash". The command appears only once the tool finishes.S4 Add the call's arguments to EventList.ToolStarted. They are already on the pending part when the tool starts.
G10 One directory per sessionadditionalDirectories can't be honored.Defer until a multi-root session is needed.
G11 Missing public APIsThis is why F3's deep imports exist.S1 A public way to read a session's effective config, e.g. Session.configuration(id) returning the resolved model and thinking level. S3 Control.run returning the turn's outcome (succeeded, failed with SessionFailure, or interrupted, plus the last stop reason), which removes the event bookkeeping in F1 and F2. S8 A public transcript decoder over ContextCodec.decodeMessage for replay (F10). S10 A "usable models" query that knows which providers have credentials, including OAuth (F8). S11 ListInput filtering by hostDir with a cursor (F9).

Highest-value core changes

  1. S3 Control.run returns the outcome. This simplifies F1 and F2 for every client, including the RPC server.
  2. S2 Persist session config. This fixes the restart regression that ACP clients hit whenever the editor restarts the agent.
  3. S5 A tool approval hook. This is the largest missing ACP feature and a safety issue in its own right.

Fix order for the PR

  1. F3 and F4: switch to public APIs (Session.attach, hostDir).
  2. F1, F2 and F7: stop reasons and error mapping, using typed events.
  3. F5, F6 and F8: a single parser for model values, validation, settings-driven defaults.
  4. F9, F10, F14 and F15: cleanup and tests.
Appendix

Reproducing the live test

From the repo root after pnpm install, build aikit once and generate the catalog, then drive the server with any ACP client:

(cd packages/aikit && pnpm run build)
node packages/aikit/dist/pack/cli.mjs modelgen ./models.gen.json

# server under test (stdio)
node --conditions=development packages/codework/src/index.ts acp --home /tmp/acp-home

# client sequence
initialize                 { protocolVersion: 1 }
session/new                { cwd: "/abs/project", mcpServers: [] }
session/set_config_option  { configId: "model", value: "openrouter/meta/muse-spark-1.3-contributor" }
session/prompt             { prompt: [{ type: "text", text: "Reply with exactly: PONG" }] }
session/cancel             (notification, about 4 s into a long prompt)

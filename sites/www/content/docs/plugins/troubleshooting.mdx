When a plugin fails, CodeWork prints a short report with a stable error slug, the entry as you wrote it, the settings file that declared it, and a hint:

```text
error[plugin-not-compiled]: Stripping types is currently unsupported for files under node_modules
reference: @acme/codework-tool-proc@1.2.0
declared in: /work/app/.codework/settings.jsonc
id: acme.tool.proc
hint: a plugin installed from git or npm must ship compiled javascript; build it and commit or publish the output
```

The slug in `error[...]` is the same string `codework plugin list` shows in place of a plugin ID, and the same one that appears in logs. Search for it on this page.

## Start with plugin list

`codework plugin list` checks every configured entry without installing anything. Each row either resolves to a plugin ID or shows the slug of what went wrong:

```bash
codework plugin list --verbose
```

`--verbose` adds the full message and the settings file behind each entry, which is usually enough to see the problem.

## Errors by slug

### The entry itself

| Slug                        | What it means                                                            | Fix                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `plugin-unsupported-source` | The entry is not a path, package spec, or git spec CodeWork can install. | Paths start with `./`, `../`, `~/`, `/`, or `file:///`. Remote tarball URLs are not supported.      |
| `plugin-not-found`          | A local path points at nothing.                                          | Check the spelling. Relative paths resolve from the folder of the settings file that declares them. |
| `plugin-escapes-root`       | A local package's `exports` resolve outside it, or it has no `name`.     | Keep the package's entrypoint inside its own folder, and give a package with `exports` a `name`.    |

### Installing

| Slug                    | What it means                                                      | Fix                                                                             |
| ----------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| `plugin-not-installed`  | The plugin is declared but its package is not in the local store.  | Run `codework plugin install`.                                                  |
| `plugin-resolve-failed` | The registry or git remote could not be asked what the spec means. | Check your network, the registry in `.npmrc`, and that credentials are current. |
| `plugin-fetch-failed`   | Downloading or installing the package failed.                      | Check the package name and version exist and the registry is reachable.         |
| `plugin-no-commit`      | A git install finished but its commit could not be determined.     | Name a branch, tag, or full commit SHA after `#`.                               |
| `plugin-no-entrypoint`  | The package installed but has no module to import.                 | Fix the package's `exports` or `main`.                                          |

`plugin-not-installed` is the one you will see most. CodeWork [never installs while loading](/docs/plugins/install#resolve-only-loading), so a fresh clone, a new machine, or a plugin added by a teammate needs one `codework plugin install`. A missing plugin from your user settings stops startup with this slug. A missing one from a project's settings is left out of the session with a warning that it is configured but not loaded.

### Loading

| Slug                        | What it means                                                                      | Fix                                                                                                                                               |
| --------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugin-not-compiled`       | An installed plugin ships TypeScript, which Node will not run from `node_modules`. | The plugin author must publish built JavaScript, or commit it for a git source. See [Publish a plugin](/docs/plugins/authoring#publish-a-plugin). |
| `plugin-missing-dependency` | The plugin imports a package that is not installed where the plugin lives.         | For a local plugin, install its dependencies next to it. `@codeworksh/plugin` and `effect` are always provided by CodeWork.                       |
| `plugin-import-failed`      | The module threw while being imported.                                             | Import the file directly with `node` to see its own error.                                                                                        |
| `plugin-invalid-definition` | The module imported, but its default export is not a valid plugin.                 | Default-export one `Plugin.define({ ... })` object with a `kind`, a `setup` function, and a `vendor.domain.name` ID.                              |

`plugin-invalid-definition` also covers a plugin that uses the reserved `codework.` prefix, and a `kind` other than `mcp`, `tool`, or `prompt`.

A configuration entry with both `plugin` and `package`, or with an `enabled` or `options` of the wrong type, is reported as a settings error instead: `error[settings-decode-failed]` with the file and the offending key.

### The plugin store

| Slug                    | What it means                                                   | Fix                                                                                               |
| ----------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `plugin-lock-timeout`   | Another install held the same plugin for more than two minutes. | Wait for it to finish. If nothing is running, remove the stale `.lock` folder in its store entry. |
| `plugin-marker-invalid` | A store entry is damaged, or could not be read or written.      | Remove the entry under `~/.codework/cache/plugins` and install again.                             |

## Common situations

**A plugin I added does not show up in the system prompt.** Check that it is not a configuration entry pointing at nothing. Configuration entries that match no selected plugin are ignored without an error. `codework plugin list` shows only module entries, so if your plugin is missing from it, add the module entry.

**My options have no effect.** The configuration entry must name the plugin exactly as it was loaded: the same package name, path, or the plugin's ID. If two entries configure the same plugin, only the last `options` block applies.

**I edited my local plugin and nothing changed.** A running server keeps local plugins loaded until you run `codework plugin reload`. Each `codework run` without `--server` starts a fresh process and always picks up edits.

**`plugin check` exits with an error.** A registry or remote could not be reached. CodeWork reports that instead of saying you are up to date. Try again once the network is back.

**A tool from my plugin replaced a built-in tool.** Two tools with the same `name` cannot coexist, so the later one wins. Rename your tool, or disable the built-in by ID if replacing it was the goal.

**A turn fails with `plugin setup failed: <id>`.** That plugin's `setup` threw or failed, which stops the turn. Common causes are a tool with an unknown `exposure`, writing to `ctx.plugin.mcp` from a plugin that is not `kind: "mcp"`, and `tools.update` on a tool that is not registered yet.

**My tool is registered but the model never calls it.** Check its `exposure`. Only `direct` and `model` tools are offered every turn; `deferred` tools wait for `toolsearch`, and `codemode` and `hidden` tools are never offered.

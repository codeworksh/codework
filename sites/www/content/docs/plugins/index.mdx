Plugins are how CodeWork learns new things. A plugin can give the agent a new tool, change how an existing tool behaves, or add instructions to the system prompt. Everything CodeWork does out of the box, from running shell commands to reading your `AGENTS.md`, is itself a plugin.

## How plugins work

A plugin is a JavaScript module that default-exports one plugin definition. You name it in a [settings file](/docs/plugins/configuration), install it with the [CLI](/docs/plugins/install), and CodeWork loads it at the start of every session.

1. **Declare it.** Add an entry to the `plugins` array in `.codework/settings.jsonc` (for a project) or `~/.codework/settings.jsonc` (for you).
2. **Install it.** `codework plugin add` installs and declares in one step. On a fresh checkout, `codework plugin install` fetches everything the settings already name.
3. **Run.** Each session loads the installed plugins, runs their `setup`, and hands the resulting tools and prompt to the model.

Loading never touches the network. If a plugin is declared but not installed, CodeWork tells you to run `codework plugin install` instead of quietly fetching it. See [resolve-only loading](/docs/plugins/install#resolve-only-loading).

<Callout type="warn" title="Only install plugins you trust">
	A plugin's code runs inside the CodeWork process with your user's access, and CodeWork has no permission prompts:
	tools a plugin registers run without asking. CodeWork never runs install scripts, but the plugin itself is trusted
	once it loads.
</Callout>

## Plugin kinds

Every plugin declares a `kind`, which is the part of the agent it extends. The kind also decides when it runs: all tool plugins are set up before any prompt plugin, so a prompt plugin always sees the complete tool set.

| Kind     | What it does                                                                                                         | Example                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `tool`   | Registers tools the model can call, patches another tool's description, or guards calls with before and after hooks. | A `list_processes` tool that runs `ps` inside the sandbox.  |
| `prompt` | Writes into the system prompt: the foundation, the shared `rules` list, or a section of its own.                     | A house-style plugin that appends your team's coding rules. |

Within one kind, plugins run in the order their entries are written, which is what lets one plugin build on another.

## Built-in plugins

CodeWork ships these plugins and turns most of them on by default. You can switch any of them on or off from settings by ID.

| ID                            | Kind   | Default | What it adds                                                                  |
| ----------------------------- | ------ | ------- | ----------------------------------------------------------------------------- |
| `codework.tool.bash`          | tool   | On      | Run shell commands in the session's sandbox.                                  |
| `codework.tool.read`          | tool   | On      | Read files.                                                                   |
| `codework.tool.write`         | tool   | On      | Create or overwrite files.                                                    |
| `codework.tool.edit`          | tool   | On      | Make targeted edits to existing files.                                        |
| `codework.tool.grep`          | tool   | Off     | Search file contents.                                                         |
| `codework.tool.find`          | tool   | Off     | Find files by name.                                                           |
| `codework.tool.ls`            | tool   | Off     | List a directory.                                                             |
| `codework.prompt.default`     | prompt | On      | The base system prompt, tool guidelines, and standing rules.                  |
| `codework.prompt.instruction` | prompt | On      | Project instructions from `AGENTS.md` or `CLAUDE.md` files in your workspace. |

Turn on the search tools with one entry each:

```jsonc title=".codework/settings.jsonc"
{
	"plugins": [
		{ "plugin": "codework.tool.grep", "enabled": true },
		{ "plugin": "codework.tool.find", "enabled": true },
	],
}
```

The `codework.` namespace is reserved for built-ins. Third-party plugins use their own vendor prefix, like `acme.tool.proc`.

## Where plugins come from

| Source         | Example entry                           | Notes                                                       |
| -------------- | --------------------------------------- | ----------------------------------------------------------- |
| npm registry   | `@acme/codework-tool-proc@1.2.0`        | Exact versions, ranges, and tags all work.                  |
| git repository | `github:acme/codework-tool-proc#v1.2.0` | Branches, tags, and commits. Subdirectories with `::path:`. |
| local file     | `./plugins/house-style.ts`              | Loaded in place. TypeScript works with no build step.       |

Installed packages live in a shared store under `~/.codework/cache`, so ten projects using the same plugin share one copy. Nothing is ever written into your project except the settings entry.

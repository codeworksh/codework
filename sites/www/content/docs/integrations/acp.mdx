## Overview

The [Agent Client Protocol](https://agentclientprotocol.com) (ACP) is an open standard for connecting coding agents to editors. The editor owns the interface: the chat panel, the file picker, the diff view. The agent owns the work: models, tools, and sessions.

`codework acp` turns the CLI into an ACP server. Your editor launches it as a child process and talks to it over standard input and output (stdio). You get the same agent, models, plugins, and session history you have in the terminal, inside the editor you already use.

![CodeWork building a Snake game in Zed's Agent Panel](/images/docs/zed/zed-thread.png)

## Start the ACP server

```bash
codework acp
```

You don't normally run this yourself. You tell your editor to run it, as in the [Zed setup](#zed) below. It accepts the [global flags](/docs/cli/reference#global-flags) `--home`, `--database`, and `--user-config-dir`.

## Transport and message format

- **Transport:** stdio. The editor writes requests to CodeWork's stdin and reads responses and notifications from its stdout.
- **Messages:** JSON-RPC 2.0, one message per line (newline-delimited JSON).
- **Protocol version:** ACP v1.
- **Logs:** written to stderr, since stdout is reserved for the protocol.

## Request flow

1. `initialize`: CodeWork reports its name, version, and capabilities.
2. `session/new`: CodeWork creates a session in the editor's project folder. That folder's `.codework/settings.jsonc` applies, as if you'd run the CLI from it.
3. `session/prompt`: CodeWork streams its answer, reasoning, and tool calls back as `session/update` notifications. Then it returns a stop reason: `end_turn`, `max_tokens` when the reply hit the model's output limit, or `cancelled`. A failed turn returns an error instead. Each session runs one prompt at a time.
4. `session/cancel`: stops the running prompt of that session only.
5. `session/set_config_option`: changes the session's model or thinking effort.
6. `session/list` and `session/load`: list the folder's past sessions, newest first, or reopen one and replay its full history.
7. `session/fork`: forks a thread at its latest message. The new thread belongs to the same CodeWork session, and the editor sees it as a new ACP session.

When the editor closes the connection, CodeWork interrupts anything still running and stops any sandboxes it manages.

## Authentication

ACP sessions use the credentials already in your CodeWork home. The editor can't sign you in, so do it once from the terminal before connecting:

```bash
codework auth login --openai-codex
```

Or pass an API key in the environment the editor launches CodeWork with, such as `OPENROUTER_API_KEY` or `GEMINI_API_KEY`. See [Models & Pricing](/docs/models) for every provider.

## Sessions and configuration

ACP sessions are regular CodeWork sessions, stored in the same database as the ones you start with `codework run`. Your editor's history and the CLI see the same sessions.

Each thread of a CodeWork session appears as its own ACP session. A fork made with `session/fork` or `codework thread fork` shows up in the session list, and you can load and prompt it like any other. The `main` thread keeps the CodeWork session's ID. Loading a fork also replays the history it inherited.

Each session has two settings, which the editor shows as pickers:

- **Model:** every model from the providers CodeWork has credentials for. The session's current model stays listed even if its credentials are gone.
- **Thinking Effort:** the reasoning levels the current model supports. Hidden for models without reasoning.

New sessions start on the default model from your [settings](/docs/customize/settings). CodeWork titles a session from its first prompt and tells the editor.

## Permissions

CodeWork has no permission prompts. It runs every tool, including shell commands and file edits, without asking the editor first, and works on files directly rather than through the editor.

ACP sessions run locally in your project folder. Use [`codework run --sandbox-driver`](/docs/sandboxes/) when you want the work to run in an isolated sandbox.

## Prompt content

| Content                     | Support                                       |
| --------------------------- | --------------------------------------------- |
| Text                        | Yes                                           |
| Images                      | PNG, JPEG, GIF, or WebP                       |
| Mentioned files, selections | Yes, sent as embedded context with the prompt |
| Resource links              | Yes, passed to the model as a link            |
| Other binary files          | No, the prompt is rejected                    |

A model that doesn't accept images gets a note in place of each image.

If a plugin in your settings fails to load, CodeWork shows a warning in the conversation so you see it without digging through logs.

## Zed

[Zed](https://zed.dev) has built-in ACP support. Register CodeWork once and it shows up next to Zed's own agent in the Agent Panel.

### 1. Find the CodeWork binary

Zed may not see your shell's `PATH` when it's opened from the Dock or Start menu. Get the absolute path to be safe:

```bash
which codework
```

You'll get something like `/Users/you/Library/pnpm/bin/codework`. Use that wherever the config below says `codework`.

### 2. Add CodeWork as a custom agent

Open **Agent Settings**, go to **External Agents**, click **Add Agent**, and choose **Add Custom Agent**. Zed opens your settings file with a new `agent_servers` entry. Fill it in like this:

```json title="~/.config/zed/settings.json"
{
	"agent_servers": {
		"CodeWork": {
			"type": "custom",
			"command": "codework",
			"args": ["acp"],
			"env": {}
		}
	}
}
```

- `command` is the CodeWork binary. Use the absolute path from step 1 if `codework` alone doesn't work.
- `args` must include `acp`. Add any global flags after it, such as `["acp", "--home", "/Users/you/.codework-zed"]`.
- `env` is passed to CodeWork. Put an API key here if Zed wouldn't otherwise see it, for example `{ "OPENROUTER_API_KEY": "..." }`. Then pick a model such as **DeepSeek V4.1 Flash** from the model picker.

![Zed settings with the CodeWork agent server](/images/docs/zed/zed-settings.png)

### 3. Start a session

1. Open a project folder in Zed. CodeWork works in this folder.
2. Open the Agent Panel from the status bar or the command palette.
3. Open the new-thread menu and choose **CodeWork** under External Agents.
4. Type a prompt and press `enter`. Each new Zed thread is a new CodeWork session.

![Choosing CodeWork from the new thread menu](/images/docs/zed/zed-new-thread.png)

You can bind a key to `agent: new external agent thread` to start one straight away.

### Working in a session

- **Add context:** type `@` to mention a file or symbol, or add a selection to the conversation. Paste or drop images if your model accepts them.
- **Switch models and thinking effort:** use the pickers at the bottom of the panel. Search the model picker by display name, such as "DeepSeek V4.1 Flash", not by its `openrouter/...` ID. Changes apply from the next prompt, and Zed remembers your choice as `default_config_options.model` in the CodeWork entry of its settings.
- **Set a project default:** to start every session in a project on the same model, set `model` in that project's [`.codework/settings.jsonc`](/docs/customize/settings).
- **Stop a turn:** click stop. The partial answer stays in the session.
- **Pick up where you left off:** open the Threads Sidebar (`cmd-alt-j` on macOS, `ctrl-alt-j` on Linux and Windows), open **Thread History**, click **Import Threads**, and select CodeWork. Opening an imported session replays the full conversation.

## Other editors

Any editor that speaks ACP can run CodeWork with the same command, `codework acp`. See the [list of ACP clients](https://agentclientprotocol.com/overview/clients).

## Troubleshooting

**CodeWork doesn't appear in the Agent Panel.** Check that `agent_servers` is at the top level of your Zed settings and the JSON is valid.

**The session never starts.** Zed couldn't run the command. Use the absolute path from `which codework`. If you installed CodeWork with pnpm, make sure the `node` it runs with is version 24 or later.

**The model picker is empty or missing a provider.** CodeWork only lists providers it has credentials for. Run `codework auth status --openai-codex` in a terminal, or add the API key to `env`.

**A plugin warning appears in the conversation.** Run `codework plugin install` in the project folder, or `codework plugin list --verbose` to see why it failed.

**Something else.** Run `dev: open acp logs` from Zed's command palette to see the raw messages between Zed and CodeWork.

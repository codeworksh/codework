## What a Sandbox Adds

A sandbox is the environment a session works in: a filesystem and a shell. Every session has exactly one, and choosing it decides several things at once:

- **The file and shell tools.** `read`, `write`, and `edit` act on its files, and `bash` runs commands in its shell.
- **Project instructions.** `AGENTS.md` and `CLAUDE.md` are found by walking up from its working directory.
- **Plugin tools.** A plugin that works through the sandbox reaches the same files and shell.

Swap the sandbox and all of this moves with it. The agent, its tools, and your plugins stay the same.

## Kinds of Sandbox

| Kind                               | Drivers         | Where the work happens                                          |
| ---------------------------------- | --------------- | --------------------------------------------------------------- |
| [Local](/docs/sandboxes/local)     | local           | Your folder and your shell. The default.                        |
| [Virtual](/docs/sandboxes/virtual) | memory, sqldb   | An in-memory filesystem and an emulated bash. No real programs. |
| [Remote](/docs/sandboxes/remote)   | daytona, vercel | A separate machine in the cloud.                                |

Pick the one that fits your use case. The wider the environment, the more model-directed work can read, change, run, and reach.

## Choose a Sandbox

Pass `--sandbox-driver` when you start a session:

```bash
codework run --sandbox-driver memory "Draft a README for a CLI tool"
```

A session keeps its sandbox for life, so leave the flag off when you continue one with `--session`. Editor sessions over ACP always use your local folder.

## Reuse or Attach

Start a new session in a sandbox CodeWork already created with `--sandbox-id <id>`. Its files are still there, and a stopped remote sandbox starts again.

To use a remote sandbox you created yourself, pass its provider ID with the driver:

```bash
codework run --sandbox-driver daytona --sandbox-provider-id <id> "Inspect the repository"
```

CodeWork uses an attached sandbox but never stops it.

## When Sandboxes Stop

CodeWork stops the sandboxes it creates:

- `codework run` stops its sandbox when the run ends.
- `codework serve` keeps them running between sessions and stops them when the server shuts down.
- `codework acp` stops them when the editor disconnects.

## Safety

<Callout type="warn">
	CodeWork runs every tool without asking. The sandbox is the only boundary, and `local` has none: the agent can do
	anything you can do from your shell. Plugin code runs inside CodeWork itself, so only install plugins you trust.
</Callout>

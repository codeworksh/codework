CodeWork reads `AGENTS.md` and `CLAUDE.md` files from your workspace and adds them to its system prompt. Use them for what every session should know: how to build and test, conventions, and things to avoid.

This is the built-in `codework.prompt.instruction` plugin. It is on by default.

## File Names

In each directory, CodeWork uses the first of these files that exists and can be read:

1. `AGENTS.override.md`
2. `CLAUDE.override.md`
3. `AGENTS.md`
4. `AGENTS.MD`
5. `CLAUDE.md`
6. `CLAUDE.MD`

Only one file per directory is used. If a directory has both `AGENTS.md` and `CLAUDE.md`, only `AGENTS.md` is read. An `.override.md` file replaces the regular one in its directory, which is handy for personal instructions you keep out of git.

An empty file still claims its directory. It adds nothing to the prompt, and the names below it in that directory are skipped.

## Which Directories

CodeWork starts at the session's working directory and walks up through every parent to the filesystem root. Each directory along the way can contribute one file.

- **Parents are included.** Instructions at the repository root apply when you work in a subfolder.
- **Subfolders are not.** Files in directories below the working directory are not read.
- **Your home folder counts only as a parent.** There is no global instructions file. A `~/AGENTS.md` loads when the working directory is somewhere under your home folder, like any other parent.

The search runs inside the session's [sandbox](/docs/sandboxes/), from the working directory up to the sandbox root. With the default local sandbox that is your own disk. In a virtual or remote sandbox, files on your machine are not read.

When the working directory is a git worktree nested inside the main checkout, a file in the main checkout's root is skipped if the worktree has a file with the same name, so the same instructions are not added twice.

## How They Appear in the Prompt

Every file found goes into the `<project_context>` section of the system prompt, farthest directory first and the working directory last, so the closest file has the final word. Each file is wrapped in a tag that names its path:

```text title="System prompt"
<project_context>
Project-Specific Instructions & Guidelines:

<project_instructions path="/home/me/work/api/AGENTS.md">
...
</project_instructions>

<project_instructions path="/home/me/work/api/services/billing/AGENTS.md">
...
</project_instructions>
</project_context>
```

File content is added as written. There is no size limit, so keep files short: everything in them is sent with every request. Files are read again before each model call, so edits apply from your next message.

## Example

```md title="AGENTS.md"
# API

- Use pnpm. Never npm or yarn.
- Run `pnpm check` and `pnpm test` before you call a task done.
- Database access goes through `src/db/`. Don't write raw SQL elsewhere.
- Ask before adding a new dependency.
```

## Turning It Off

Disable the plugin in your [settings](/docs/customize/settings):

```jsonc title=".codework/settings.jsonc"
{
	"plugins": [{ "plugin": "codework.prompt.instruction", "enabled": false }],
}
```

## Going Further

Project instructions are one prompt plugin. To add rules, context, or whole sections to the system prompt in code, write your own [prompt plugin](/docs/plugins).

CodeWork connects to [MCP](https://modelcontextprotocol.io) servers over stdio or streamable HTTP. Their tools reach the model as `mcp__<server>__<tool>`.

## Where Servers Run

MCP servers always run on your machine, the one running CodeWork, whatever sandbox the session uses.

- A stdio server starts in the session's directory when the session runs in the local sandbox, otherwise in the session's folder on your machine.
- HTTP servers are called from your machine.
- Output too large to show, and binary files, are saved to your OS temp directory.

A sandbox is only where files and commands run. To give MCP access to a remote sandbox, build an HTTP MCP server that talks to it.

## Configure Servers

User servers go in `~/.codework/mcp.json`, project servers in `.codework/mcp.json`. The format matches other MCP clients, so you can copy entries over:

```json title="~/.codework/mcp.json"
{
	"mcpServers": {
		"filesystem": {
			"command": "npx",
			"args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
		},
		"docs": {
			"url": "https://example.com/mcp",
			"headers": { "Authorization": "Bearer ${DOCS_TOKEN}" }
		}
	}
}
```

| Field                                            | Server | Meaning                                                                                           |
| ------------------------------------------------ | ------ | ------------------------------------------------------------------------------------------------- |
| `command`, `args`, `env`, `cwd`                  | stdio  | One executable and its arguments, not a shell line. `cwd` is relative to where the server starts. |
| `url`, `headers`                                 | HTTP   | A streamable HTTP endpoint. SSE is not supported.                                                 |
| `enabled`, `timeout`, `exposure`, `toolExposure` | both   | Off switch, per-request timeout in seconds (default 60), and which tools the model sees.          |
| `scope`                                          | both   | Who shares one running server: `session` (default), `space` or `app`.                             |

`env` and `headers` values can use `${NAME}` or `$NAME` for an environment variable (`$$` for a literal `$`), or `!command` to use a command's output. A command runs once, and its output is reused until CodeWork restarts.

Servers that need you to sign in are not supported yet.

A broken file or entry is reported and skipped. The other servers still connect.

## Project Overrides

A project entry with the same name replaces a user entry. An entry with only `enabled`, `exposure` or `toolExposure` changes just those, so credentials stay in your user file:

```json title=".codework/mcp.json"
{ "mcpServers": { "internal-tools": { "enabled": false } } }
```

## Sharing a Server

By default each session runs its own copy of a server. `scope` shares one instead:

| Scope     | Shared by                                 | A stdio server starts in |
| --------- | ----------------------------------------- | ------------------------ |
| `session` | Threads of one session in the same folder | The thread's directory   |
| `space`   | Sessions in the same folder and sandbox   | The folder               |
| `app`     | Every session                             | Where CodeWork started   |

When the session's sandbox isn't the local one, `session` and `space` servers start in the session's folder on your machine instead. `app` servers are sent no roots, so a path like `.` in their arguments means where CodeWork started.

Share a server only when it keeps no per-session state. Sessions whose settings for a server differ never share it.

## Which Tools the Model Sees

`exposure` is `direct` (the default), `hidden`, `codemode` or `deferred`:

| Exposure   | The model                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------ |
| `direct`   | Sees the tools like any other tool.                                                        |
| `deferred` | Finds them with `toolsearch` (turn on `codework.tool.toolsearch`), then sees them.         |
| `hidden`   | Never sees them.                                                                           |
| `codemode` | Can't reach them yet: they need codemode, which is coming. CodeWork warns once per thread. |

`toolExposure` sets single tools, by name or with `*` patterns:

```json
{ "exposure": "hidden", "toolExposure": { "search_*": "direct" } }
```

Servers with resources also add `list_mcp_resources`, `list_mcp_resource_templates` and `read_mcp_resource`, when at least one of them is `direct`.

## Connections

- Servers connect in the background. A message waits up to 10 seconds for servers it starts whose tools the model sees or has found: all of them at first, then new or changed ones.
- If a server stops, the next call starts it again. A server that fails to connect stays failed until you change its settings.
- Edits to `mcp.json` apply from your next message. Changing only `exposure` or `toolExposure` keeps the server running.
- A server no running session needs closes after 10 minutes, and starts again when one does.
- Server log messages go to `~/.codework/mcp.log`.

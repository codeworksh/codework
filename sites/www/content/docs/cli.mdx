The `codework` CLI is the most direct way to use CodeWork. Every other interface is built on it: `codework acp` serves editors, and `codework serve` starts the RPC server.

## Install

```bash
npm install -g @codeworksh/cli
```

Requires Node.js 24 or later. Run `codework --help` or `codework <command> --help` for every flag.

## Run a session

`codework run` starts a session, sends one prompt, streams the answer, and prints the session ID.

```bash
codework run "Inspect the failing tests"
```

Continue the same session by passing its ID:

```bash
codework run --session <session-id> "Now fix them"
```

| Flag                         | Description                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------- |
| `-s`, `--session <id>`       | Continue an existing session                                                    |
| `-C`, `--cwd <path>`         | Working directory for a new session                                             |
| `--provider <id>`            | Model catalog provider ID                                                       |
| `--model <id>`               | Model ID                                                                        |
| `--thinking <level>`         | `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`                    |
| `--sandbox-driver <driver>`  | Run a new session in a sandbox, such as `daytona` or `vercel` (default `local`) |
| `--sandbox-id <id>`          | Reuse an existing sandbox instance                                              |
| `--sandbox-provider-id <id>` | Attach to an existing remote sandbox by its provider ID                         |
| `--server <url>`             | Run against a [CodeWork server](/docs/rpc) instead of a local harness           |

## Commands

| Command                 | What it does                                                          |
| ----------------------- | --------------------------------------------------------------------- |
| `codework run`          | Start or continue an agent session                                    |
| `codework models`       | List the model catalog. `providers` and `refresh` subcommands         |
| `codework auth`         | `login`, `status`, `refresh`, and `logout` for subscription providers |
| `codework plugin`       | `add`, `remove`, `install`, `list`, `check`, `update`, and `reload`   |
| `codework session link` | Anchor a session to a project directory                               |
| `codework serve`        | Start the [RPC server](/docs/rpc)                                     |
| `codework acp`          | Start the [ACP server](/docs/acp) for editors                         |

## Global flags

These work on every command that boots a local harness.

| Flag                | Description                                                                     |
| ------------------- | ------------------------------------------------------------------------------- |
| `--home`            | CodeWork home for settings, credentials, cache and data (default `~/.codework`) |
| `--database`        | SQLite database path, or `:memory:`                                             |
| `--user-config-dir` | Directory whose `settings.jsonc` replaces the user settings in `--home`         |

## Environment variables

| Variable               | Description                                                         |
| ---------------------- | ------------------------------------------------------------------- |
| `CODEWORK_MODELS_FILE` | Pin the model catalog to a file you manage                          |
| `CODEWORK_MODELS_TTL`  | How old the catalog may get before a refresh (default `15 minutes`) |

Provider API keys such as `ANTHROPIC_API_KEY` are listed in [Models & Pricing](/docs/models#api-keys).
